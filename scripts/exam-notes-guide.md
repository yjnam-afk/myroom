# 작업: 해설집 스캔을 읽고 토픽 정리로 옮기기

정보관리기술사 학습 사이트에는 교재에 없는 토픽이 많다. 그 토픽을 다룬 **해설집 스캔 이미지**가 있다.
입력 파일(`in-NN.json`)의 토픽마다 이미지(`images` — 절대 경로, Read 도구로 본다)를 차례로 읽고, 해설에 **적힌 내용만** 구조화해 옮긴다.

## 가장 중요한 규칙
- **지어내지 않는다.** 해설에 없는 정의·항목·수치·사례를 넣지 않는다. 아는 지식으로 보태지 않는다.
- 글자는 해설 표기 그대로 옮긴다. 줄일 때는 해설 문장에서 조사·군말만 덜어 낸다(용어를 다른 말로 바꾸지 않는다).
- 안 읽히는 글자는 추측하지 않는다 — 그 칸·행을 뺀다.
- 해설이 그 토픽(`name`)을 실제로 다루지 않으면(문제가 딴 주제) `ok: false` 와 `reason` 만 적는다.
- 해설 머리의 문제·출제영역·난이도·해설자 표, 「출제배경」「참고문헌」「기출 이력」은 옮기지 않는다.

## 출력 (`out-NN.json`) — 입력과 같은 수·같은 차례의 객체 배열
```json
{
 "name": "입력의 name 그대로",
 "ok": true,
 "lead": "해설 1번 제목의 리드문(「자원 점유의 무한 대기, 교착상태의 개요」에서 「자원 점유의 무한 대기」). 없으면 \"\"",
 "definition": "해설의 정의·개념 문장 그대로(한두 문장). 없으면 \"\"",
 "features": ["해설에 「특징」으로 적힌 것만, 짧은 명사구 3~5개. 없으면 빈 배열"],
 "keywords": ["해설에 나오는 핵심 용어 5~7개(해설 표기 그대로)"],
 "tables": [
  {"caption": "해설의 소제목 그대로(「가. ○○의 구성요소」→「○○의 구성요소」)", "headers": ["구분", "항목", "설명"], "rows": [["…", "…", "…"]]}
 ],
 "figures": ["해설에 그림(개념도·구성도)이 있으면 그 제목이나 무엇을 그린 그림인지 한 줄. 그림 속 글자는 옮기지 않는다"],
 "pros": {"장점": ["해설에 있으면"], "단점": ["해설에 있으면"]},
 "uses": ["해설에 적용 사례·활용 분야가 있으면 그 항목 이름"]
}
```
- **표**: 해설의 표를 열 구성 그대로 옮긴다(머리글도 해설 그대로). 열을 합치거나 새 열을 만들지 않는다. 한 칸은 40자 안쪽으로(넘으면 조사·수식어를 던다), 칸 안 줄바꿈은 `\n`.
  표가 아니라 글머리표 목록이면 `["항목", "설명"]` 2열 표로 옮긴다. 표는 해설에 나온 차례대로, 많아도 5개까지(본문 단락의 표를 먼저, 결론·고려사항은 뒤).
- `pros`·`uses` 는 해설에 그런 항목이 없으면 `{}` / `[]`.
- 한 문제가 여러 개념을 묻는 해설이면, `name` 의 개념을 다룬 부분만 옮긴다.

## 마무리
- 저장소 파일은 건드리지 않는다. 결과 파일 하나만 쓴다.
- 다 쓴 뒤 `python3 -c "import json;print(len(json.load(open('…'))))"` 로 JSON 이 유효한지, 개수가 입력과 같은지 확인한다.
- 답은 「옮김 N · ok:false N」 한 줄이면 된다.
