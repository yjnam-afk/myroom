# "쉽게 이해하기" 쪽집게 강사 규격 (hook·scene·map 재작성)

대상 독자: 개발 경험이 없는 기술사 수험생. IT 용어를 하나도 모른다고 가정한다.

## 절대 규칙

### hook (한 문장 요약)
- 초보가 그대로 읽고 "아 그런 거구나" 해야 한다. 전문용어 금지.
- 60자 이내. 일상 언어만. 예: "요리사는 요리만 하고, 주방 준비는 건물주가 다 해 주는 방식입니다."

### scene (한 장면 — 비유)
- **2문장 구조 고정**:
  1. 문장①: 일상 비유 상황 제시 — 전문용어 0개. 식당·주방·아파트·택배·도서관·학교·병원·은행 등 누구나 아는 소재.
  2. 문장②: 그 비유를 **그대로 이어받아** 기술 동작을 설명. 시험 용어는 반드시 "쉬운말(용어)" 괄호 병기로만 등장.
- 비유 연결어 필수: 처럼/같이/마치/~라고 생각하면/~인 셈 중 하나 이상.
- 길이 80~200자(한글 기준). 세 문장 넘기지 말 것.
- 괄호 밖 본문에 금지: 동적으로, 정적으로, 기반으로, 수행한다, 제공한다, 관리한다,
  최적화, 아키텍처, 프레임워크, 메커니즘, 프로토콜, 인터페이스, 모듈, 컴포넌트,
  알고리즘, 파라미터, 방법론, 표준화, 추상화. (괄호 안에는 허용)
- 교재 정의문을 복사해 붙이지 말 것. 정의는 exam 필드가 담당한다.

### map (비유 ↔ 시험 용어 매핑)
- `as`(비유 쪽): **순수 일상어만**. 영문 약어·전문용어 금지. "주문 접수 창구"처럼 비유 세계의 사물.
- `real`(용어 쪽): 시험 용어 그대로 — **변경 금지**.
- `note`: 짧은 보충(선택). scene의 비유와 같은 세계관을 유지할 것.
- scene에서 쓴 비유와 map의 as가 **같은 세계관**이어야 한다(식당 비유면 map도 식당 사물).

### 건드리지 말 것
- why, mechanism, usage, links, exam 필드는 **절대 수정 금지** (시험용 정보).
- 키(id), 객체 구조, 따옴표 스타일, 파일의 다른 부분 일절 변경 금지.

## 좋은 예 (서버리스 컴퓨팅)
```ts
hook: "요리사는 요리만 하고, 주방 준비·청소는 건물주가 다 해 주는 방식입니다.",
scene: "내 식당을 차리면 손님이 없는 날에도 주방 임대료가 나갑니다. 공유주방을 쓰면 주문이 들어온 순간에만 주방을 빌리고 쓴 시간만큼만 내는데, 서버리스가 딱 이 방식입니다 — 서버 준비·관리(인프라)는 클라우드가 맡고 개발자는 요리(코드)만 올립니다.",
map: [
  { as: "쓴 만큼 내는 공유주방", real: "FaaS", note: "주문(이벤트) 올 때만 실행" },
  { as: "주문 접수 창구", real: "API Gateway", note: "손님 주문을 주방에 전달" },
  { as: "미리 만들어 둔 반찬 가게", real: "BaaS", note: "인증·저장소를 사다 씀" },
  { as: "출입증 검사", real: "OAuth 인증", note: "" },
],
```

## 나쁜 예 → 고치는 법
- ✗ "IT 거버넌스는 이사회·경영진 수준의 의사결정 체계로 IT 자원과 프로세스를 기업 전략에 정렬시켜…"
  → 정의문 복사. 비유가 없다.
- ✓ "집안 살림을 각 방 식구가 제멋대로 사면 냉장고에 우유만 세 통 쌓입니다. 집안 회의에서 '뭘 사고 뭘 아낄지' 규칙을 정하듯, IT 거버넌스는 회사 전체의 IT 지출·결정 규칙을 경영진이 정하는 것입니다."

## 검사기
```
python3 scripts/check-easy.py g01 g02        # 지정 청크만
python3 scripts/check-easy.py extras         # subnoteExtras.ts
```
위반 0건(PASS)까지 고친다. 검사기를 통과시키려고 규칙을 우회(비유 연결어만 끼워 넣기 등)하지 말 것 — 문장 전체가 비유로 읽혀야 한다.
