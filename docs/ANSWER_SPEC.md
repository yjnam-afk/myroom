# 정보관리기술사 모범답안 작성 규격 (현행 — 140회 기준)

`src/data/modelAnswers.json` 은 `{ "<문제id>": { period, title, answer, source } }` 형태.
- period: "1교시" | "2교시" | "3교시" | "4교시"
- title: 문제 핵심 주제(30자 이내)
- source: `Claude(클로드) 작성 · <회차> <교시> 기출 · ITPE 서브노트·해설 근거 · 답안작성방법론 적용`
- answer: 아래 규격의 마크다운 문자열

검사기: `python3 scripts/check-answer-format.py <회차번호> [파일경로]` — PASS 필수.

## 교재 인용 원칙
- 교재 정의에서 **색(빨강·파랑)으로 강조된 단어는 채점 키워드**다.
  정의를 옮기거나 34~35자로 줄일 때 **그 단어를 빼지 않는다** —
  줄이는 대상은 조사·수식어이지 강조어가 아니다.

## 절대 금지 (공통)
- **mermaid·코드블록(```) 절대 금지** — 앱이 제거해 화면에 보이지 않는다(규칙 6-1).
  개념도가 필요하면 "동작 흐름: A → B → C" 한 줄 텍스트 + 두음신공으로 대체.
- 3단표의 **3열은 2열을 다른 말로 바꿔 쓰지 않는다** — 2열에 없는 정보(결과·기준값·조건·대상)를 준다.
  - 나열표 `| 구분 | 키워드 | 설명 |` → 설명은 **6~12자 명사구**.
  - 판정·대응표 `| 구분 | 점검 항목 | 판정·조치 |`(대응 방안·영향 등) → 3열 **12~30자**,
    수치·라이선스명·표준명 같은 **기준값을 길이 때문에 깎아내지 말 것**.
- 모든 표 바로 아래에 **간글 1줄**(`- …` 형태의 해설 한 줄).
- 나열 항목엔 **두음신공**(첫 글자 암기법) 제시.
- 근거는 앱의 토픽 자료(교재 서브노트·커널 학습카드·topicDetails)를 우선 사용.

## 1교시 (용어형·약술형)
```
문) <문제 전문>

답)

## 1. <리드문(10~14자, 배경·필요성 구절)>, <토픽>의 정의
- <정의 — 공백 제외 34~35자, 한 문장>
- 특징) <특징1>, <특징2>, <특징3>   ← 정확히 3개, 쉼표(또는 ·) 구분

## 2. <토픽>의 <구성요소|동작원리|유형> (일도일표)
가. <소제목>
- 동작 흐름/구조 한 줄 + 두음신공
나. <소제목>
| 구분 | 키워드 | 설명 |
|---|---|---|
| … | … | <6~12자, 2열 재진술 금지> |
- <간글 1줄>

## 3. <활용·비교·전망 등 확장형 마무리>
- 2~4줄
```
- **비교형 문제**("A와 B의 정의", "비교" 포함): 1번 절부터 `가. A의 정의` / `나. B의 정의`
  대칭 구조로, 각각 정의 34~35자 + `특징)` 3개. 2번 절은 상세 비교표, 3번 절은 확장형.

## 2~4교시 (서술형 — ITPE 4단락)
```
문) <문제 전문(가/나/다 포함 한 줄)>

## I. 서론 — <리드문>, <토픽>의 등장
- <정의 — 공백 제외 34~35자>
- 특징) <3개>
- (필요성) 1줄 / (등장배경) 1줄

## II. (가) <문제의 가 항목>
### 가. <소제목> (두음신공: **…**)
| 구분 | 키워드 | 설명 |
…
- <간글 1줄>

## III. (나) <문제의 나 항목>
…같은 구조…

## IV. (다) <문제의 다 항목> 및 결론
- 마지막에 실무 적용·최신 동향·기술사 관점 제언 2~3줄
```
- 절 제목은 `## I.` `## II.` `## III.` `## IV.` 로마자 4단락(초과 금지).
- 문제의 가/나/다 하위 항목은 빠짐없이 각자의 단락에 배치.
